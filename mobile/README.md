# FDA: Forever Doesn't Allow — Android app

An Android wrapper around the game in `../fda.html`. The whole game ships
**inside the APK** — no network at all, including the fonts.

## Two build paths

| | `native/` | `mobile/` (Capacitor) |
|---|---|---|
| Needs Google's SDK? | **No** — Debian/Ubuntu packages only | Yes (`dl.google.com`) |
| Builds green in CI? | **Yes** (~30 s) | **Yes** (~90 s) |
| APK size | ~407 KB | ~3.7 MB |
| Plugin ecosystem | None (plain WebView) | Full Capacitor plugins |
| Play Store ready | Needs work | Closer (bump `targetSdk`) |

**CI builds both on every change** — see
[`.github/workflows/android.yml`](../.github/workflows/android.yml). Each run
uploads its APK as a downloadable artifact, so you never need a local Android
SDK to get a build.

Use `native/` when you want a tiny APK or a machine that cannot reach Google's
Maven. Use Capacitor when you want the plugin ecosystem, or when you head for the
Play Store.

> **Why two?** Capacitor 6 requires Android Gradle Plugin 8.x, which Google
> publishes **only** to its own Maven repository. Maven Central's newest AGP is
> 2.3.0, from 2017. In an environment that cannot reach `dl.google.com` the
> Gradle build is simply impossible — but a plain `aapt2` + `javac` + `dx` +
> `apksigner` pipeline still works, so that is what `native/` does.

## The Capacitor build

> **Not buildable in every environment.** Capacitor 6 needs Android Gradle
> Plugin 8.x and androidx, which Google publishes **only** to its own Maven
> repository — androidx is a 404 on Maven Central. Anywhere that cannot reach
> `dl.google.com`, this path is impossible and `native/` is the answer.
> It **does** build green on GitHub-hosted runners, which is what CI uses.

## Build it

**Prerequisites:** JDK 17+ and the Android SDK (easiest via Android Studio, which
sets `ANDROID_HOME` for you). Node 18+.

```bash
cd mobile
npm install
npm run apk:debug
```

The APK lands at:

```
mobile/android/app/build/outputs/apk/debug/app-debug.apk
```

Install it on a plugged-in phone with USB debugging on:

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Or open the project in Android Studio and press Run:

```bash
npm run open
```

### Scripts

| Command | What it does |
|---|---|
| `npm run build` | Regenerates `www/index.html` from `../fda.html` |
| `npm run sync` | `build`, then copies web assets + plugins into the Android project |
| `npm run apk:debug` | `sync`, then `gradlew assembleDebug` |
| `npm run apk:release` | `sync`, then `gradlew assembleRelease` (needs signing, below) |
| `npm run fonts` | Re-downloads and re-inlines the bundled fonts (needs network) |
| `npm run open` | Opens the project in Android Studio |

## How it stays in sync with the web game

`../fda.html` is the single source of truth. `tools/build-www.mjs` reads it and
applies exactly the changes a WebView needs — swapping the Google Fonts `<link>`
for the bundled stylesheet, adding `viewport-fit=cover`, injecting the mobile
CSS and the Android shell shim.

**The script asserts every substitution.** If someone edits `fda.html` so that a
replacement no longer matches, the build *fails* with a message telling you to
update the transform, rather than quietly shipping a half-converted app. The
build also refuses to emit a bundle containing any `<link>`, `<script>` or
`<img>` that would fetch from the network at render time — that check is what
guarantees the app works in aeroplane mode.

So: **edit `fda.html`, then run `npm run sync`.** Never edit `www/index.html`. It is
generated and gitignored.

## What the wrapper adds

- **Offline fonts.** The build inlines Press Start 2P, VT323, Space Mono and Inter as
  base64 woff2 (347 KB) in `www/fonts/fonts.css`, generated by
  `tools/fetch-fonts.mjs`. All four are SIL Open Font Licence 1.1, which permits
  bundling and redistribution. Without this the app would fall back to system
  fonts and lose its entire look.
- **Hardware back button.** It closes an open Sources or Reskins sheet first.
  otherwise confirms before quitting, because leaving mid-run discards the
  playthrough.
- **External links.** Citation links and the "Aileron Games" link open in the
  system browser via Custom Tabs rather than navigating the WebView away from
  the bundled app.
- **Touch targets.** Menu options hold to ≥48dp, Android's minimum.
- **Display cutout handling** via `env(safe-area-inset-*)`, and a compacted nav
  on small screens.
- **Portrait lock**, dark status bar, and a splash screen matching the game.
- **Icons** generated by `tools/make-assets.py` from the game's own sprite data —
  the launcher icon is literally the patient and IV pole from the trail.

## Regenerating assets

```bash
python3 tools/make-assets.py     # icons + splash screens (needs Pillow)
npm run fonts                    # re-inline the fonts (needs network)
```

## Signing a release build

Create a keystore once:

```bash
keytool -genkey -v -keystore fda-release.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias fda
```

Then create `android/keystore.properties` (gitignored, never commit it):

```properties
storeFile=/absolute/path/to/fda-release.jks
storePassword=…
keyAlias=fda
keyPassword=…
```

`android/app/build.gradle` picks this up automatically. If the file is absent,
the release signing config stays unregistered, and debug builds still work.

```bash
npm run apk:release
```

## Before submitting to Google Play

Two things are deliberately left at Capacitor 6's tested defaults rather than
changed blind in an environment that could not compile or run them:

1. **`targetSdkVersion` is 34.** Play requires new and updated apps to target a
   more recent API level than that. Bump `compileSdkVersion` and
   `targetSdkVersion` in `android/variables.gradle`, then **test on a device** —
   Android 15 (API 35) enforces edge-to-edge, which is why the CSS already uses
   `env(safe-area-inset-*)`, but nobody tested that path here.
2. **`versionCode`/`versionName`** in `android/app/build.gradle` are `1` / `1.0`.

Play also wants an AAB rather than an APK: `cd android && ./gradlew bundleRelease`.

## What we checked, and what we did not

**Verified** — the exact `www/` payload that goes into the APK, driven in
headless Chromium at 412×915 with touch emulation and **every non-`file://`
request aborted**, i.e. hard offline:

- Full playthrough to the end card: **0 network requests, 0 JS errors.**
- `Press Start 2P`, `VT323` and `Inter` all confirmed loaded from the base64
  payload (`document.fonts.check`), including Inter on the end card.
- No horizontal overflow on the title, the trail, the Three Doors layout, the
  end card, or the Sources sheet.
- Menu tap targets measured at 66px (≥48dp required).
- Gravesite persistence across runs via `localStorage`.

For the `native/` path we also built an APK and inspected it.
signatures, dex integrity, contents, and a full playthrough of the payload
extracted back out of the finished APK. See [`native/README.md`](native/README.md).

**Both Gradle and the native pipeline now build green in CI**, so
`assembleDebug` is no longer an open question — see the Android workflow runs.

**Not verified** — needs a physical device:

- The Capacitor plugin bridge at runtime: status bar colour, splash hide, the
  hardware back button, and Custom Tabs link opening. The shim is written
  defensively (every plugin call is presence-checked, so a missing plugin
  degrades rather than throws) but it has not executed on a device.
- Icon and splash rendering on a real launcher.
- **Neither APK ran on physical hardware.** Everything above is
  a successful compile plus a browser-level run of the payload.
